Public API ​

Zstandard.ZstdCompressionContext Type
julia
ZstdCompressionContext(; level=3, checksum=false, dict=nothing, long=false,
                       content_size=true, dict_id=true, magicless=false, prefix=nothing,
                       window_log, hash_log, chain_log, search_log, min_match,
                       target_length, strategy)

A compression context with fixed parameters, reused across calls (as a libzstd ZSTD_CCtx): its match-finder tables, entropy scratch and output buffer persist, and parameters are validated once. Use it with compress(ctx, data), or compress!(ctx, out, data) to write into a vector you reuse as well, which avoids allocating a result per call (worthwhile for many small inputs). The keywords mean the same as for compress.

A context must not be used by several tasks at the same time.

julia
ctx = ZstdCompressionContext(level=5, checksum=true)
out = UInt8[]
for msg in messages
    compress!(ctx, out, msg)
    send(out)
end
source
Zstandard.ZstdDecompressionContext Type
julia
ZstdDecompressionContext(; dict=nothing, magicless=false, prefix=nothing)

A decompression context reused across calls (as a libzstd ZSTD_DCtx): its decoding tables persist. Use it with decompress(ctx, data), or decompress!(ctx, out, data) to decode into a vector you reuse. Data may hold several concatenated and skippable frames; dict is used for frames that need it. With magicless=true, frames have no magic numbers (see compress).

A context must not be used by several tasks at the same time.

source
Zstandard.ZstdFrameHeader Type
julia
ZstdFrameHeader

Information from a Zstandard frame header, as returned by frame_header.

  • content_size: decompressed size, or nothing if the header does not record it

  • window_size: window size required to decode the frame

  • dict_id: dictionary ID, 0 if none

  • checksum: whether the frame ends with an XXH64 content checksum

  • single_segment: whether the frame is a single segment (window = content size)

  • header_size: size of the frame header in bytes, including the magic number

source
Zstandard.ZstdSeekTable Type
julia
ZstdSeekTable

The seek table of a seekable Zstandard archive (see compress_seekable): for each frame its compressed and decompressed sizes, offsets, and (if recorded) the low 32 bits of the XXH64 of its content. length(table) is the number of frames; table.content_size the total decompressed size.

source
Zstandard.ZstdSequence Type
julia
ZstdSequence(offset, literal_length, match_length)

One Zstandard sequence: literal_length literal bytes, then match_length bytes copied from offset bytes back (as libzstd's ZSTD_Sequence, with offset the actual distance, not a repeat-offset code). A sequence with offset == 0 and match_length == 0 is a block delimiter: its literals end the block.

Zstandard.ZstandardCompressor Function
julia
ZstandardCompressor(; level=3, checksum=false, dict=nothing, window_log=nothing, ...)

A TranscodingStreams.jl codec compressing to the Zstandard format, for use with transcode, TranscodingStream, etc. Available once TranscodingStreams is loaded. Accepts the parameter and frame keywords of compress (window_log, ..., content_size, dict_id, magicless), and size_hint (see ZstdCompressorStream) for streams whose size is not pledged, and long and nthreads as for ZstdCompressorStream.

TranscodingStreams does not pass flush on to codecs, so flushing a TranscodingStream does not make the data written so far decodable; write TranscodingStreams.TOKEN_END to end the frame, or use ZstdCompressorStream, whose flush emits a block that decoders can read before the frame ends.

julia
using Zstandard, TranscodingStreams
compressed = transcode(ZstandardCompressor(level=5), data)
stream = TranscodingStream(ZstandardCompressor(), open("out.zst", "w"))

Zstandard.compress Method
julia
compress(data; level=3, checksum=false, dict=nothing, nthreads=1, long=false,
         content_size=true, dict_id=true, magicless=false, prefix=nothing, rsyncable=false,
         target_block_size=nothing,
         window_log, hash_log, chain_log, search_log, min_match, target_length, strategy)
    -> Vector{UInt8}

Compress data (a byte vector or string) into a Zstandard frame.

level ranges from -7 (fastest) to 22 (strongest); 0 selects the default level 3, as in libzstd. With checksum=true an XXH64 content checksum is appended. With a ZstdDictionary, its content serves as history and, for formatted dictionaries, its entropy tables and repeat offsets are used; the frame records the dictionary ID. When compressing many small inputs with one dictionary, pass a PreparedDictionary from prepare_dictionary instead: it is much faster, and its level is then used (a conflicting level throws an ArgumentError). Inputs larger than 1 GiB are written as several concatenated frames.

The remaining keywords override individual parameters of the level, with the meaning of libzstd's advanced parameters (ZSTD_c_windowLog etc.); see Zstandard.Encoder.parameter_overrides. For example, compress(data; level=19, window_log=24) searches matches up to 16 MiB back.

With nthreads > 1, inputs larger than a few window sizes are split into jobs compressed in parallel tasks (within a single frame, as libzstd's nbWorkers); start Julia with several threads (julia -t N) to benefit. The output differs slightly from single-threaded compression. Not combined with dict or long (those always run on one thread).

With long=true, long-distance matching finds repetitions up to 128 MiB apart (as zstd --long); the frame then declares a window of up to 128 MiB, which decoders must be willing to allocate.

With target_block_size = n (1340 to 131072; libzstd's ZSTD_c_targetCBlockSize), blocks are split so that each compressed block is about n bytes, which lets a streaming decoder start on each sooner (lower latency, slightly lower ratio). Not applied to multithreaded jobs.

With rsyncable=true (as zstd --rsyncable), the input is cut into jobs at content-defined points (as libzstd's ZSTD_c_rsyncable): each job starts with fresh repeat offsets and entropy tables, so a local change to the input changes the output only near it, and rsync-style tools can transfer the difference efficiently. The ratio is slightly lower. Jobs run in parallel with nthreads > 1.

With prefix = bytes, those bytes serve as history the data may refer to (libzstd's ZSTD_CCtx_refPrefix, as zstd --patch-from): the frame records nothing about them, and must be decoded with the same prefix (decompress(frame; prefix=bytes)). Unless window_log is given, the window is widened to reach back into the whole prefix (up to 128 MiB); combine with long=true for large inputs. Not combined with dict.

Frame header options (libzstd's ZSTD_c_contentSizeFlag, ZSTD_c_dictIDFlag and ZSTD_f_zstd1_magicless): content_size=false leaves the content size out of the header, dict_id=false the dictionary ID (the decoder must then be given the right dictionary), and magicless=true omits the 4-byte magic number; such frames are decoded with decompress(data; magicless=true).

source

compress_bound(n) -> Int

Largest possible size of the frame compress produces for n bytes of input (libzstd's ZSTD_COMPRESSBOUND): n + n÷256, plus a little for inputs under 128 KiB. Useful to preallocate the output vector of compress!. (Seekable archives add their seek table on top.)

Zstandard.compress_seekable Method
julia
compress_seekable(data; frame_size=1 MiB, checksum=true, nthreads=1, level=3, ...) -> Vector{UInt8}

Compress data into the Zstandard seekable format (as libzstd's contrib/seekable_format): independent frames of frame_size bytes of content each (at most 1 GiB), followed by a seek table in a skippable frame. Any Zstandard decoder decodes the whole archive; decompress_range decodes just a range, touching only the frames it overlaps. With checksum=true the seek table records an XXH64-based checksum of each frame's content, verified on decoding. Frames are compressed in parallel on up to nthreads tasks. Other keywords (level, dict, window_log, ...) are passed to compress for each frame.

source
Zstandard.compress_sequences Method
julia
compress_sequences(data, seqs::AbstractVector{ZstdSequence}; level=3, checksum=false,
                   validate=true) -> Vector{UInt8}

Encode data, described by the sequences seqs (as libzstd's ZSTD_compressSequences), into a Zstandard frame: the literals come from data, matches from the sequences. If seqs contains block delimiters (see ZstdSequence), they set the blocks (each at most 128 KiB) and must cover data exactly; otherwise blocks of 128 KiB are formed, splitting sequences as needed, and bytes after the last sequence are literals (as libzstd's ZSTD_sf_explicitBlockDelimiters and ZSTD_sf_noBlockDelimiters). With validate=true every match is also checked against data (otherwise a wrong match silently changes what the frame decodes to). level selects the entropy coding effort.

source
Zstandard.decompress Function
julia
decompress(data::AbstractVector{UInt8}, dict::Union{Nothing, ZstdDictionary}=nothing;
           nthreads=Threads.nthreads())

Decompress Zstandard compressed data, which may contain several concatenated and/or skippable frames. Optionally, a ZstdDictionary can be provided. Throws a ZstdError if the data is malformed.

When data holds several frames (at least 128 KiB in total), they are decoded in parallel on up to nthreads tasks; a single frame is always decoded on one thread. The result does not depend on nthreads.

With magicless=true, frames are read without magic numbers (as written by compress(data; magicless=true)); skippable frames cannot occur then. With prefix = bytes, frames written with that reference prefix are decoded (see compress).

Zstandard.Streaming.ZstdCompressorStream Type
julia
ZstdCompressorStream(io::IO; level=3, checksum=false, dict=nothing, pledged_size=nothing,
                     close_io=true, size_hint=nothing, content_size=true, dict_id=true,
                     magicless=false, long=false, nthreads=1, window_log, ...)

A streaming Zstandard compressor implementing the writable IO interface. Data written to the stream is compressed into a single frame and written to io block by block. flush emits all pending data as a complete block, so everything written so far can be decoded.

Without pledged_size the frame header does not record the content size. With pledged_size = n, it does (so decoders can preallocate, and frame_content_size reports it), the compression parameters are sized to n as in one-shot compress, and exactly n bytes must be written: writing more throws an ArgumentError, and so does close after writing fewer.

Without a pledge, size_hint = n sizes the parameters for about n bytes (libzstd's ZSTD_c_srcSizeHint) without recording a size or limiting the input.

window_log, hash_log, chain_log, search_log, min_match, target_length and strategy override the level's parameters, content_size, dict_id, magicless and target_block_size set frame options, and prefix sets a reference prefix, as for compress (the window is sized for the prefix plus the pledged size or size hint). With long=true, long-distance matching finds repetitions up to 128 MiB apart, as for compress (the stream then buffers up to 128 MiB of history, less when a smaller pledged_size or size_hint is given). With nthreads > 1, input is cut into jobs compressed in parallel tasks (as libzstd's nbWorkers; jobs are four windows long, so the stream buffers that much); output is written as jobs complete, in order, and flush and close wait for them. Neither is combined with dict or prefix, and long not with nthreads.

close finishes the frame and, if close_io is true, closes io (pass close_io=false to keep writing to io, e.g. an IOBuffer read afterwards).

source
Zstandard.Streaming.ZstdDecompressorStream Type
julia
ZstdDecompressorStream(io::IO, dict::Union{Nothing, ZstdDictionary}=nothing;
                       max_window_size=128 MiB)

A streaming Zstandard decompressor that implements the IO interface. Decoded data is produced one block at a time; memory use is bounded by the frame's window size plus one block. Frames declaring a window larger than max_window_size (default 128 MiB, as libzstd) are rejected with a ZstdError, so untrusted input cannot make the decoder allocate more; raise it to read frames written with a larger window (e.g. zstd --long=30). With magicless=true, frames are read without their magic number, and prefix decodes frames written with that reference prefix (see compress).

Zstandard.Encoder.parameter_overrides Method
julia
parameter_overrides(; window_log, hash_log, chain_log, search_log, min_match,
                      target_length, strategy) -> ParameterOverrides

Validate explicit compression parameters (each nothing = the level's value), with the meaning of libzstd's ZSTD_c_* parameters:

  • window_log (10-30): log2 of the maximum match distance (window size)

  • hash_log (6-27): log2 of the main hash table size

  • chain_log (6-28): log2 of the chain / secondary table size (unused by the greedy and lazy strategies, whose row-based match finder sizes rows from search_log, as in libzstd)

  • search_log (1-26): log2 of the number of match candidates searched

  • min_match (3-7): minimum match length searched for (the match finders use 4-7 for fast/dfast, 4-6 for greedy/lazy, 3-4 for btopt/btultra)

  • target_length (0-131072): for fast, a step size (acceleration); for btopt/btultra, a length taken without optimizing (unused by greedy/lazy, as in libzstd)

  • strategy: :fast, :dfast, :greedy, :lazy, :lazy2, :btlazy2, :btopt, :btultra or :btultra2 (libzstd's strategies)

Parameters are adapted to the input size afterwards, as in libzstd (e.g. the window shrinks for small inputs).

Zstandard.Encoder.train_dictionary Method
julia
train_dictionary(samples; dict_size=112640, level=3, algorithm=:fastcover,
                 k=nothing, d=nothing, steps=8, f=20, nthreads=Threads.nthreads()) -> Vector{UInt8}

Train a formatted Zstandard dictionary from samples (a vector of byte vectors), as zstd --train: dictionary content is built from the most frequent segments of the samples, then entropy tables are added (finalize_dictionary). Use the result with parse_dictionary.

algorithm=:fastcover (libzstd's default) counts hashed dmers of d bytes (2^f buckets); algorithm=:cover counts each distinct dmer exactly, once per sample (ZDICT_trainFromBuffer_cover; slower, sometimes better). Parameters not given are optimized, as ZDICT_optimizeTrainFromBuffer_*: segment sizes k from 50 to 2000 in steps steps and dmer sizes d of 6 and 8 are each tried by compressing a held-out quarter of the samples, in parallel on up to nthreads tasks (the result does not depend on it).

AbstractXXH64

Supertype of XXH64 implementations used for Zstandard frame content checksums. To use another implementation, define a subtype T and four methods:

julia
xxh64(impl::T, p::Ptr{UInt8}, n::Int, seed::UInt64)::UInt64   # one-shot
